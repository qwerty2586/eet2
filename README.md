# eet2

[![Go](https://github.com/qwerty2586/eet2/actions/workflows/go.yml/badge.svg)](https://github.com/qwerty2586/eet2/actions/workflows/go.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/qwerty2586/eet2.svg)](https://pkg.go.dev/github.com/qwerty2586/eet2)

Go client for the Czech **electronic sales registration EET 2.0**, in force from 1 January 2027
(Act No. 180/2026 Coll., EET interface version 4). It builds the sale data message, signs it with
the cash register certificate, sends it and returns the confirmation code (POK).

> **This library was generated by [Claude](https://claude.ai) (Anthropic)** from the tax
> administration's official technical documentation. The code is tested, and sending has been
> verified against the live EET playground ([how](docs/testing.md)). Please review it before
> using it in production.

## Installation

```sh
go get github.com/qwerty2586/eet2
```

## Usage

```go
d, err := eet2.NewDispatcher(eet2.PlaygroundService, "CA_EETPlayground-CZ00000019.p12", "password")
if err != nil {
	log.Fatal(err)
}

resp, err := d.SendPayment(eet2.Receipt{
	EicPopl:    "CZ00000019",
	IdJednotky: 303,
	IdPokl:     "RECEPCE",
	PoradCis:   "2027/000123",
	DatTrzby:   time.Now(),
	CelkTrzba:  decimal.RequireFromString("250.00"),
})
if err != nil {
	log.Fatal(err)
}
fmt.Println("POK:", resp.Pok)
```

All `Receipt` fields and the EET reply attributes keep their Czech names (`EicPopl`, `PoradCis`,
`CelkTrzba`, `Opakovane`, `Pok`, …) so they match the official specification. Everything else is
in English.

## Features

- **Certificate from a file or from memory:** `.p12` as `[]byte`, PEM, or your own
  `crypto.Signer` (HSM, KMS). `CheckP12` verifies a certificate and its password offline.
  → [docs/certificates.md](docs/certificates.md)
- **Exact amounts:** `decimal.Decimal` instead of `float64`. The library does not round; amounts
  with more than two decimal places are rejected. → [docs/amounts.md](docs/amounts.md)
- **Resending after a failure:** `eet2.IsRetryable(err)` and `Opakovane: true`.
  → [docs/retries.md](docs/retries.md)
- **Certificate renewal through the CA EET API:** `RenewCertificate` and `Confirm`, swapped at
  runtime without a restart. → [docs/certificates.md](docs/certificates.md), ready-made program
  in [example/certificate_renewal](example/certificate_renewal)
- **Validation before sending** against the formats from the specification. The sale fields are
  described in the [`Receipt`](https://pkg.go.dev/github.com/qwerty2586/eet2#Receipt) documentation.

## Examples

```sh
# send a test sale to the playground
go run ./example/playground -p12 CA_EETPlayground-CZ00000019.p12 -password <password>

# renew the cash register certificate
go run ./example/certificate_renewal -p12 register.p12 -password <password> -out register-new.p12
```

## Limitations

- The electronic signature of confirmation messages is not verified yet. The reply's
  authenticity relies on the TLS connection with a verified server certificate.
- The library does not provide a resend queue or sale storage; that belongs in the application.
- Certificate renewal has not been tried against the real CA EET yet, only against a simulation
  built from the official API specification.

## Inspiration

- [prochac/eet](https://github.com/prochac/eet): Go client for the original EET (2016–2022).
  The simplicity of its API (`NewDispatcher`, `Receipt`, `SendPayment`) is the direct model for
  this library.

## Sources

- [EET 2.0 – Pro vývojáře](https://eet.gov.cz/cs/pro-vyvojare): interface specification, data
  message field descriptions, access information and EET certificate authority documentation.
